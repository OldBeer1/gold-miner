# 第 13 步：关间自动存档与新版记录

状态：已完成（2026-10-03，v1.1.0）。实际实现与验证见 IMPLEMENTATION_PLAN.md 文末交接和 VALIDATION.md 新版记录。前置：第 01～12 步已完成，现有无限生存游戏可启动。

读取项目 `AGENTS.md`、[README](../README.md)、[原无限规格](../ENDLESS_SPEC.md)、[新扩展规格](../SAVE_DIFFICULTY_SPEC.md)、[进度与最新交接](../IMPLEMENTATION_PLAN.md) 及本文件。新需求以新扩展规格为准。

检查 Git 工作区、`js/storage.js`、`js/rules.js`、`js/game.js`、页面结构和现有保存检查。复用入口快照与现有存储组织方式。

## 2. 本步完成后

主页能够继续已有挑战。关内退出后，从同一关起点重新开始；商店退出后，保留已完成的交易。失败结束本轮，新版成绩与旧版分开保存。

本步先沿用现有难度和固定商品价格。第 14 步负责新难度，第 15 步负责动态价格，阶段性运行说明应明确这一点。

## 3. 实现范围

1. 增加独立的挑战存档，区分关卡入口、成功关间和商店状态，并保存结构与玩法版本。
2. 进入关卡且尚未计时、抓取时保存入口状态；成功结算、商店创建及每次成功购买后更新存档。
3. 主页增加“继续游戏”及保存位置提示；返回主页保留存档；新挑战覆盖已有存档前确认，取消后保留原挑战。
4. 恢复当前关起点的完整布局、奖励、钱包、炸药、总收入和增益；本关收入归零，物体、时间和钩子恢复开局。
5. 恢复商店原商品、报价、已扣款的钱包、库存、购买次数和下一关效果；正确重建交易对象关联。
6. 实际失败后删除本轮存档，保留最高记录；不能读取失败挑战重试原关。
7. 新版最高记录从零开始，仅继承旧音效。旧存储键及旧成绩保留，不改写。
8. 增加版本与数据校验，处理损坏、未知版本及存储读写删除异常，提供准确的界面提示。

关内运行中的钱包和物体状态不能覆盖入口快照。不能既保存本关收益，又在继续时恢复已经回收的物体。

继续游戏时新建计时基准，关闭页面期间不消耗游戏时间。成功收入不能在恢复结果或商店时重复累计。

建议存储键和字段见新扩展规格第 2、5 节；无需增加运行依赖或账号系统。

## 4. 验证与完成条件

| 检查 | 必须得到的结果 |
| --- | --- |
| 关内采矿后刷新 | 同一关从头开始，入关资源恢复，已取得收益撤回，地图和奖励不变 |
| 使用炸药、护符或时间奖励后退出 | 恢复入口时的资源与效果，不复制奖励 |
| 成功结算后立即退出 | 已通过关卡不丢失，总收入只累计一次，可进入同一商店 |
| 商店购买两件后刷新 | 资金、库存、效果、商品和“2 / 4 件”保持一致 |
| 返回主页与新挑战 | 可以继续原挑战；取消覆盖不改存档，确认后创建新种子和初始资源 |
| 真正失败后刷新 | 不能继续失败挑战，最高记录仍保留 |
| 数据迁移与异常 | 新成绩从零开始，旧音效继承、旧键不变；异常有提示且页面仍可玩 |

执行针对性的规则与存储检查，实际浏览器验证文件直开、继续入口、刷新和交易恢复。受控布局或时钟要注明，不将其当作完整真实计时试玩。

JavaScript 改动执行语法检查，并运行相关原规则回归。只有实际实现和本步检查通过后，才能标记第 13 步完成。

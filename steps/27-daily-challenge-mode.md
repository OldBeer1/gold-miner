# 第 27 步：每日挑战与日期规则

状态：已完成，随合并版 v1.4.0 正式交付（2026-10-05）。目标版本：v1.4.0。前置：[第 26 步](26-seed-challenge-mode.md) 已完成。

本轮用户明确要求第 23～28 步合并推进并统一交付 v1.4.0；原 v1.3.0 不单独发行。分步范围统一按合并版执行，最终状态与证据以实施计划和验收记录为准。

## 1. 开始前读取

按 [AGENTS.md](../AGENTS.md) 顺序读取 [README](../README.md)、[现行游戏规格](../GAME_SPEC.md)、[实施计划](../IMPLEMENTATION_PLAN.md)、[验收记录](../VALIDATION.md)，再读 [功能规划](../FEATURE_ROADMAP.md) 第 13 节及第 26 步定稿规则与接口。

## 2. 本步完成后

玩家可以进入固定 UTC+8 日期对应的每日矿井，反复练习并保留当日个人最佳，跨午夜继续原有挑战时不换地图。

## 3. 实现范围

1. 固定 UTC+8 日期格式、字符编码、日期／模式／规则版本到 32 位 Seed 的派生算法，保存规则版本与算法说明；不依赖操作系统本地时区。
2. 每日模式复用有限赛程、初始状态、商店事件规则与统一保存，保证同日期同版本具有一致挑战内容。
3. 活动挑战保存开始日期、规范化 Seed 与规则。午夜后新每日局使用新日期；旧局继续沿用原日期，不重新抽地图。
4. 每日成绩按日期、模式和规则版本独立保存；允许重复尝试，只更新个人最佳；成绩比较采用第 26 步既定顺序。
5. 页面展示日期、规则版本、Seed 与个人最佳，分享文本加上日期；确认／取消覆盖保持同一活动挑战约束。
6. 清楚说明离线日期依赖设备时钟，不能验证真实日期或防作弊。不增加服务器、在线排行榜或连续签到压力。

## 4. 验证与完成条件

用明确日期与时区条件验证 UTC+8 午夜前后、不同操作系统时区、跨日继续、相同日期重复尝试、规则版本变化及系统时间回退时的记录行为。不能把不同日期或版本的个人最佳覆盖为同一项。

检查日期派生纯逻辑、同日期内容确定性、恢复不重抽、成就与统计隔离；实际浏览器验证每日入口、覆盖确认、日期显示、个人最佳与分享。受控日期测试注明条件，设备时钟不可信的边界如实展示。

## 5. 交接要求

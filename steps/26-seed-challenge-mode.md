# 第 26 步：Seed 挑战与模式隔离

状态：后续规划。目标版本：v1.4.0。前置：[第 25 步](25-events-validation-delivery.md) 及 v1.3.0 完成实际验收。

## 1. 开始前读取

按 [AGENTS.md](../AGENTS.md) 顺序读取 [README](../README.md)、[现行游戏规格](../GAME_SPEC.md)、[实施计划](../IMPLEMENTATION_PLAN.md)、[验收记录](../VALIDATION.md)，再读 [功能规划](../FEATURE_ROADMAP.md) 第 8、13～14 节及第 25 步交接。核实当时玩法、存档和事件目录，不假定仍使用 v1.1.0 结构。

## 2. 本步完成后

玩家能够输入规范化整数 Seed 开始有限赛程、继续同一挑战、完成赛程或失败结束，查看独立成绩和可复现分享文本。每日日期派生在第 27 步完成。

## 3. 实现范围

1. 定稿挑战规则：初版建议 20 关、钱包 0、炸药 1、无入口增益；明确允许的商店、事件与其他规则，写入稳定规则版本。无限模式保留无终点。
2. 提供 0～4294967295 整数 Seed 的规范化与输入反馈；不把空输入、负数、小数、超范围或非有限数悄悄转成有效 Seed。
3. 模式、规则版本、种子、关号和相关状态参与确定性；沿用用途分离和预定奖励值，正确处理不同幸运增益的映射。
4. 完成最后一关后生成“赛程完成”报告，不出现下一关商店或第 21 关；失败沿用当前成绩口径。
5. 无限／Seed 记录分开，比较相同规则的通过关数、有效成绩和有效采矿时长；模式与规则版本不兼容时不混排。
6. 活动存档保存模式、赛程和规则；仍使用一份活动挑战，切换模式创建新局须遵循已有覆盖确认，取消保留原局。
7. 成就用明确模式白名单，原无限成就默认仅无限可得；生涯与报告按模式记录，不串用最高纪录。
8. 分享文本包括模式、规范化 Seed、规则版本、通过数和成绩；只生成可复制内容，不自动发送到外部服务。

## 4. 验证与完成条件

检查 Seed 0／最大值及各类非法输入，相同 Seed／版本／模式在不同打开方式中的布局、事件、商店和奖励值一致；不同增益映射说明准确。覆盖赛程成功、失败、恢复、模式切换确认／取消、独立纪录、新增结束原因与旧无限存档迁移。

实际浏览器验证输入、模式入口、复制分享、报告与三种视口；运行相关确定性、规则、存储和 JavaScript 语法检查。不得将离线成绩称为可信在线排名。

## 5. 交接要求

更新 [实施计划](../IMPLEMENTATION_PLAN.md)、[验收记录](../VALIDATION.md)、[README](../README.md) 和挑战定稿规则，写明模式 ID、Seed 规范化、规则版本、赛程结束与比较顺序。每日功能与整版验收仍待后续。

下一步：[第 27 步：每日挑战与日期规则](27-daily-challenge-mode.md)。

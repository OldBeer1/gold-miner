## 3. 实现范围

1. 在首次生成受影响商店前确定下一关事件，并保存已解析 ID、参数、相关布局或生成输入与固定报价。
2. 商店提示下一关事件及真正生效的变化，报价显示、可购判断与扣款来自同一来源。进入商店后不能暗中更改价格或商品规则。
3. 入关时恢复事件结果，展示矿层名称和简明说明；保持单循环、基础操作、暂停和输入隔离。
4. 接入统一成长提交与报告，记录实际事件，不把看预告当作研究／回收；只有另行定义后才增加新事件成就，旧 ID 与收藏分母保留。
5. 明确普通旧存档与新事件存档的版本兼容；旧关保持原布局和已支付交易，不在恢复时强加新事件。
6. 保留四件限购、炸药库存、时间上限和护符范围；确需新规则时在规格中明示并补对应边界，而非借事件修改隐含行为。

## 4. 验证与完成条件

实际浏览器验证事件预告、开始关卡、成功入店、购买、刷新、返回和失败报告；事件、布局、报价、库存、增益、统计不重抽或重复累计。检查普通／事件入口和商店的旧版本迁移、损坏与拒绝存储反馈。覆盖三种既有视口、暂停、静音和输入隔离，执行相关规则／存储与语法检查。

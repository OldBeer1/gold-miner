# 第 07 步：完整验收、调参与交付

前置：[第 06 步](06-visuals-and-audio.md)完成。执行约定见 [分步计划](../IMPLEMENTATION_PLAN.md)。规则来源：[原规格](../GAME_SPEC.md)第 5、9、10 节及其引用的全部玩法规则。

## 本步结果

完成原规格的整体验收，修复发现的问题，交付可实际运行的游戏和准确的说明。

## 执行范围

1. 按原规格第 10 节逐项验收，记录检查方法、结果和证据；覆盖启动、碰撞、入账、计时、道具、商店、药水、重试、暂停、保存、完整流程、可玩性和布局输入。
2. 使用实际浏览器从开始界面玩通三关，经过两次商店到通关页；另外执行失败、重试和重新开始流程。
3. 实际验证每关不购买药水时存在 60 秒内可执行的达标路线，注明使用或未使用炸药。可控状态检查与真实游玩分别记录。
4. 检查抓取耗时、遮挡关系和目标金额。普通大金块从抓到收回约 3～5 秒，深处石头约 5～7 秒；根据试玩调整必要参数，记录原值、新值和原因。
5. 汇总并运行轻量规则检查，重点覆盖单次入账、超时结算、钱包交易、药水期限、快照恢复与连续失败重试不能刷钱。
6. 修复验收发现的缺陷，复测修复项及受影响流程；必要调参后复核三关路线与完整通关。
7. 完善 README：主要文件、操作说明、直接打开方式、适用于 Windows 的可选本地服务方式、已执行检查、参数调整与实际限制。服务命令与项目实际可用环境一致。
8. 更新分步计划的最终状态和交接记录，给出可运行产物位置及最终验证结论。

## 完成标准

| 交付项 | 完成条件 |
| --- | --- |
| 可运行项目 | 按 README 实际启动，开始页与游戏可用，控制台无未处理错误 |
| 整体验收 | 原规格第 10 节每一项都有实际结果，发现的问题已修复并复测 |
| 完整流程 | 实际玩通三关并经过两次商店，另验证失败与重试 |
| 可玩性 | 三关无药水达标路线有实测证据，数值调整有原因和记录 |
| 规则检查 | 核心金额、道具和快照规则检查通过，连续重试不会刷钱 |
| 交付说明 | 文件、运行方法、验证结果和剩余限制准确，文档与最终代码一致 |

如果实际浏览器或试玩条件不足，继续完成可执行的检查，并明确列出未验证项、原因与替代检查。本步保留“进行中”状态，待整体验收补齐后再标记完成。

## 最终交接

最终回复说明完成的功能、主要文件、运行方法、实测结果、自动检查结果、调参数值和剩余问题；未执行的检查单独注明。

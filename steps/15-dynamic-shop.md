# 第 15 步：动态商店价格与界面整合

状态：已完成（2026-10-03，v1.1.0）。实际实现与验证见 IMPLEMENTATION_PLAN.md 文末交接和 VALIDATION.md 新版记录。前置：[第 13 步](13-checkpoint-save.md) 与 [第 14 步](14-staged-difficulty.md) 已完成。

## 1. 开始前读取

读取项目 `AGENTS.md`、[README](../README.md)、[原无限规格](../ENDLESS_SPEC.md)、[新扩展规格](../SAVE_DIFFICULTY_SPEC.md)、[进度与最新交接](../IMPLEMENTATION_PLAN.md) 及本文件。重点读取新规格第 2、4 节。

检查商品配置、交易校验、商店创建、关卡参数、存档恢复、卡片渲染和已有交易检查。

## 2. 本步完成后

商店按下一关难度生成固定报价，价格随难度适度上涨，购物仍有预算取舍。继续游戏后商品、报价、购买次数和交易结果保持一致。

## 3. 实现范围

1. 根据下一关难度和收益参数生成正整数价格，首次进入时固定。本店停留、购买和恢复期间不重新定价。
2. 商品卡片、钱包检查、按钮禁用原因和实际扣款使用同一报价来源。
3. 将报价纳入第 13 步商店存档及数据校验；恢复时重建正常交易关联，不重抽商品或重置购买。
4. 每次成功购买后保存扣款、库存、购买次数和增益；失败购买不改变资金或次数。
5. 检查收益倍率下的实际增值金额，更新道具描述，避免继续写死“钻石 250 → 375”等不适用数值。
6. 展示下一关关号、目标、钱包、“已购买 X / 4 件”及必要的保存提示，保持页面简洁。
7. 根据一关收入与跨关钱包校准涨幅，让后期购物仍需要预算；记录完整价格规则和调参依据。

继续保留七种商品池、固定炸药加随机三种、四槽展示、四件限购、不刷新、不补货、非炸药单店限一份、炸药库存上限五枚和跳过购买。

力量、黄金和钻石增值、延时、护符及幸运符仍沿用原效果。动态价格不能改变物品作用范围或奖励概率。

## 4. 验证与完成条件

| 检查 | 必须得到的结果 |
| --- | --- |
| 第 19、29、39 关商店 | 分别按第 20、30、40 关参数显示目标与报价 |
| 报价和扣款 | 正整数、金额一致，UI 禁用理由与规则一致 |
| 买两件后退出继续 | 原报价、资金、库存、效果及“2 / 4 件”恢复 |
| 连买炸药与第五次交易 | 每枚计一件，库存不超过五枚，限购后不扣款 |
| 缺钱、库存满或重复购买 | 交易失败，金额及购买次数不变 |
| 相同种子及同一商店 | 商品可复现，本店不重抽、不替换、不重新定价 |
| 收益倍率及道具文案 | 实际入账、卡片描述和效果范围一致 |
| 预算与布局 | 初期商品可合理购买，后期仍有预算取舍；桌面和短屏操作可用 |

预算检查包含多种商品组合、不同钱包及跳过购买的情况；记录可购买件数或组合和采用的收入样本。不能只证明价格上涨，就认定购物取舍已经成立。

执行针对性的规则交易检查、真实浏览器购买/刷新/继续检查和布局检查；必要时重新验证受本步影响的金币奖励与存档。不因纯价格变化重复不受影响的长流程。

# 第 01 步：项目骨架与开始界面

前置：无。执行约定见 [分步计划](../IMPLEMENTATION_PLAN.md)。规则来源：[原规格](../GAME_SPEC.md)第 2、3、4、9 节。

## 本步结果

建立可以直接打开的静态项目，显示中文开始界面和基础游戏场景，为第 02 步接入玩法提供稳定入口。

## 实现范围

1. 检查项目说明及配置。空项目按原规格创建 `index.html`、`styles.css`、`js/config.js`、`js/game.js` 和 `README.md`；已有项目沿用现有结构。
2. 集中放置画布尺寸、矿工锚点、矿物参数、关卡参数与道具价格等配置，取值以原规格第 4～6 节为准。
3. 建立开始界面、游戏界面及页面状态切换入口。开始按钮进入游戏场景，返回操作能回到开始界面；维护一个游戏更新循环。
4. 使用 960 × 640 逻辑画布建立背景、矿工、绳索和矿物的基础绘制，保持宽高比缩放并关闭图像平滑。此时基础几何绘制即可。
5. 建立 HUD 容器，预留关卡、收入/目标、时间、钱包、炸药和药水状态的位置。开始界面显示操作说明、开始按钮、最高记录和音效开关的位置；记录与声音行为后续接入。
6. 建立输入入口与坐标转换：仅矿区点击进入游戏输入处理，HTML 按钮点击不会传入出钩操作。游戏规则与绘制逻辑分开组织。
7. 在 README 写明直接打开页面的方式，以及当前只完成界面和场景骨架。

## 本步边界

本步结束时可以进入场景，出钩、碰撞、计分和倒计时由第 02 步实现；暂未接入的按钮或数值应体现当前阶段状态。

## 验收

| 检查 | 完成条件 |
| --- | --- |
| 本地打开 | 直接打开 `index.html` 后开始界面可见，控制台无未处理错误 |
| 页面切换 | 连续开始、返回、再次开始，页面状态正确，更新循环没有重复启动 |
| 画布缩放 | 1280×720 和 1920×1080 下保持比例，矿区输入能转换到逻辑坐标 |
| 按钮输入 | 点击开始等 HTML 按钮只执行对应操作 |
| 配置与说明 | 参数集中配置，README 的启动方法与实际一致 |

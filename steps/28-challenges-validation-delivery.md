# 第 28 步：挑战模式完整验收与 v1.4.0 GitHub 交付

状态：后续规划。目标版本：v1.4.0。前置：[第 26 步](26-seed-challenge-mode.md)、[第 27 步](27-daily-challenge-mode.md) 已完成。

## 1. 开始前读取

按 [AGENTS.md](../AGENTS.md) 顺序读取 [README](../README.md)、[现行游戏规格](../GAME_SPEC.md)、[实施计划](../IMPLEMENTATION_PLAN.md)、[验收记录](../VALIDATION.md)，再读 [功能规划](../FEATURE_ROADMAP.md) 第 13～14 节和第 26～27 步实际检查与规则。

## 2. 本步完成后

无限、每日和 Seed 三种模式完整可用，确定性、赛程、成绩与保存隔离有证据，v1.4.0 文档与独立玩家包一致，并按 [AGENTS.md](../AGENTS.md) 完成全部 GitHub 交付。

## 3. 验收与交付范围

1. 核对 Seed 输入范围、日期／版本派生、UTC+8 换日、跨午夜继续、非法数据、系统时钟变化与重复尝试。
2. 对相同模式／日期或 Seed／版本核对布局、事件、奖励值与商店，解释不同道具状态导致的合法差异；UI 和成就不能消费玩法随机序列。
3. 验证有限赛程完成后不进入第 21 关，成功／失败／放弃报告准确；不同模式纪录、个人最佳和成就白名单无串用。
4. 验证全部模式的入口、交易、结果与跨日恢复，旧无限档案与活动挑战迁移，存储异常与旧键残留不产生重复成果。
5. 执行最终规则、存储、确定性、日期和语法检查；真实浏览器覆盖入口、Seed 输入、复制分享、三类报告、成长页面、三种视口、暂停、标签隐藏与静音。
6. 原始地图、真实计时、真实输入验证代表性挑战流程；完整 20 关结束可另用明确受控条件检查，证据不能混写成真实连续通关。
7. 同步 README、最终挑战规则、实施与验收，证据采用 `survival-v140-*`，写明离线日期与成绩不提供可信竞赛保证。
8. 用现有流程制作 v1.4.0 本地 ZIP、清单和 SHA-256，按实际运行文件核对完整性，独立解压复验三种模式、继续、资料、报告与资源。

## 4. 完成与交接

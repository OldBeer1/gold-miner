# 第 03 步：三关流程与失败重试

前置：[第 02 步](02-single-level.md)完成。执行约定见 [分步计划](../IMPLEMENTATION_PLAN.md)。规则来源：[原规格](../GAME_SPEC.md)第 5、6、7、10 节。

## 本步结果

三关能够连续游玩，成功经过关间页面，失败能够重试当前关并恢复入关状态。

## 实现范围

1. 补齐第 2、3 关的固定布局、矿物数量和目标；三关都以同一个核心循环运行，坐标作为固定配置保存。
2. 实现流程：开始 → 第 1 关 → 成功结算 → 商店 → 第 2 关 → 成功结算 → 商店 → 第 3 关 → 通关结算。
3. 先完成商店页面的流程骨架：显示钱包与“开始下一关”，点击后才开始下一关计时。商品交易在第 04 步接入。
4. 进入每关时保存独立、不可被游玩状态修改的入关快照，涵盖关卡、钱包、炸药、本关药水效果与此前成功关卡累计收入；当前未购买药水时使用无效果状态。
5. 失败页提供重试当前关和返回开始界面。重试恢复快照、固定矿物、60 秒计时、零本关收入和初始钩子状态。
6. 成功结算只提交一次本关收入；失败收入只用于本次尝试展示。维持“本关收入判定目标、钱包购物、本轮总收入累计成功关卡”的职责。
7. 检查三关可达性、矿物重叠和遮挡，并初步估算无需药水时的达标路线；第 07 步进行实际试玩验证。
8. 为快照副本、连续失败重试和收入累计增加轻量自动检查。

## 本步边界

本步先完成全部页面衔接和重试数据恢复，商店购买与道具作用在第 04 步接入。重试直接进入当前关，使用当前关的入关快照。

## 验收

| 检查 | 完成条件 |
| --- | --- |
| 三关切换 | 第 1、2 关成功后先结算再进商店，第 3 关成功后进入通关页 |
| 商店等待 | 停留在商店不消耗下一关时间，开始下一关才初始化并计时 |
| 固定布局 | 每关重试后矿物位置和数量与初次进入一致 |
| 快照独立 | 游玩时修改钱包、库存和药水状态不改变已保存快照 |
| 连续重试 | 抓矿后失败，连续重试，钱包与累计成功收入没有增加 |
| 状态恢复 | 重试恢复所有快照字段、收入、时间和钩子状态 |
| 返回主页 | 返回再开始得到新一轮初始状态，无旧循环残留 |

页面流程检查可使用可控状态辅助覆盖；交接中注明方法。实际在 60 秒内玩通三关的验收留到第 07 步。

## 交接

记录三关配置、页面切换、快照创建与恢复接口、成功收入提交位置。注明第 04 步的商店购买应在进入下一关之前完成，并由入关快照接收购买后的状态。

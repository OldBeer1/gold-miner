### 第 02 步：单关核心玩法

前置：[第 01 步](completed-steps-01-16.md#step-01)完成。执行约定见 [分步计划](implementation-log-2026-10-04.md)。规则来源：[原规格](three-level-spec.md)第 4、5、6、7、10 节。

#### 本步结果

第 1 关可完整游玩：摆动、出钩、抓取、拖回、入账、倒计时、成功或失败结算，以及重新开始。

#### 实现范围

1. 配置第 1 关的固定矿物布局和目标，支持小金块、大金块、石头、钻石；布局满足原规格第 5 节的位置、数量与可达性要求。
2. 实现钩子状态：摆动 → 伸出 → 带物或空钩回收 → 摆动。出钩后锁定方向，触达边界自动回收，携带物体跟随钩子。
3. 使用上一帧至当前帧钩尖线段做碰撞检测，选择最早交点；一次只抓一个物体，被携带物体从可抓取集合移除。
4. 空格和矿区点击可出钩，长按和忙碌状态不重复触发；游戏中的空格不滚动页面，结算状态屏蔽抓取输入。
5. 实现收回到锚点才入账。分别维护本关收入、钱包和本轮总收入；前两者在收回时增加，本轮总收入在成功结算时正式累计，失败尝试不累计。
6. 使用真实经过时间运行每关 60 秒；处理长帧时兼顾时间准确与运动连续。提前达标继续游玩；归零只结算一次，在途矿物不计收入。
7. 实现第 1 关成功/失败结果页与重新开始，展示尝试收入及“时间到，未收回的矿物不计分”。新开一轮恢复初始状态。
8. HUD 随实际状态更新；为单次入账、成功累计及超时边界增加轻量规则检查。

#### 本步边界

先运行一个完整关卡。三关衔接和入关快照由第 03 步实现，道具效果由第 04 步实现；第 1 关初始炸药数量按规格为 1，此时使用功能尚未接入。

#### 验收

| 检查 | 完成条件 |
| --- | --- |
| 出钩 | 空格、点击均有效；长按或钩子忙碌时不会重复出钩 |
| 碰撞 | 同一路径近物先被抓住，低帧率检查没有越过近物抓远物的现象 |
| 回收 | 命中后带物回收，未命中到边界空钩回收，返回后恢复摆动 |
| 入账 | 抓住时金额不变，回到锚点才入账，同一矿物不能重复入账 |
| 金额累计 | 成功收入只累计一次，失败尝试不计入本轮总收入 |
| 时间边界 | 达标后继续计时；时间到只结算一次，在途物体不计分 |
| 重新开始 | 多次重新开始后矿物、金额、时间与钩子状态恢复，只有一个更新循环 |

### 第 04 步：商店、炸药与药水

前置：[第 03 步](completed-steps-01-16.md#step-03)完成。执行约定见 [分步计划](implementation-log-2026-10-04.md)。规则来源：[原规格](three-level-spec.md)第 4、6、7、10 节。

#### 本步结果

两次关间商店提供可购买的道具；炸药能解除慢速拖拽，药水在下一关正确生效，失败重试保留已付款的入关道具状态。

#### 实现范围

1. 按原规格第 6 节接入商品：炸药、力量药水、钻石增值剂。价格、倍率和库存上限集中配置。
2. 商店展示钱包、价格和效果，根据缺钱、已购买、库存已满显示可用状态；交易再次检查条件，保证钱包非负。购物只扣钱包。
3. 第 1 关免费拥有一枚炸药，余量跨关保留，可重复购买至上限。
4. 用 ↓、S 或炸药按钮销毁当前携带物体，扣一枚库存、不给收入，并切换为空钩速度回收；石头、金块、钻石均可被销毁。
5. 空钩或无库存时不消耗炸药。按键长按不会反复执行；按钮点击不触发出钩，游戏操作期间方向键不滚动页面。
6. 两种药水在每次商店各最多购买一份，进入下一关时生效，离开该关后到期；力量药水仅影响带物回收，钻石增值剂仅影响钻石收入。
7. 将购买后的钱包、库存和本关效果存入下一关快照。失败重试恢复这些值，撤销失败尝试的收入和消耗。
8. 更新 HUD 和结果文案，为交易限制、道具使用、效果期限和道具快照恢复增加轻量自动检查。

#### 验收

| 检查 | 完成条件 |
| --- | --- |
| 商店扣款 | 正确扣钱包，本关成绩和已累计收入不因购物减少 |
| 商品限制 | 缺钱禁购，同种药水不重复购买，炸药达到上限后禁购 |
| 炸药有效使用 | 带物且有库存时销毁物体，库存减一，金额不变，钩子快速空钩回收 |
| 炸药无效使用 | 空钩、无库存或非游玩页面使用时状态不变 |
| 力量效果 | 带物回收速度 ×1.5，摆动、伸出和空钩速度保持规格值 |
| 钻石效果 | 无药水按基础价值结算，有药水每颗结算 375 |
| 效果期限 | 商店购买当下不生效，只影响下一关；两种药水可同时生效 |
| 购买后重试 | 重试保留入关药水和炸药数量，钱包恢复为购买后入关值，无重复扣款 |

物体数、深度和风险密度有边界，压力增长逐渐放缓；档位仍按公式推进。目标与收益同比放大不代表实际难度增加，需结合路线压力或目标相对可采价值调整。

玩法版本或配置改变时，明确存档兼容方式；不能静默重新生成旧存档中的地图、奖励或资源。开发检查使用隔离测试存储，避免调参过程中混入实际玩家成绩。

记录目标金额、位置范围、障碍配置和收益参数的原值、新值、原因及验证结果。参数未经过验证前，不写成最终验收结论。

#### 5. 验证与完成条件

- 第 1、2、3、4、9、10、11、19、20、21、29、30、31、39、40、100、1000 关各至少 100 个种子，共至少 1700 份布局。
- 同种子复现、边界、无重叠、危险物上限、真实无道具路线和当前档位备用布局均通过。
- 明确验证 19→20、29→30、39→40 升档，以及同档目标与参数一致；布局可以不同。
- 强制候选生成失败时备用图仍可开始且压力符合档位；高关号无数值异常、无限生成或地图越界。
- 实际浏览器抓取被石头遮挡的矿物，验证清障成本、可替代路线和火药桶实际范围销毁。
- 对照旧版约 26 秒以内的候选路线记录新版分布，说明中后期压力是否提高，不能只报告目标数字变大。
- 存档恢复新关卡时，完整配置、倍率和奖励不变，继续保持第 13 步的资源边界。

执行相关规则与生成检查、JavaScript 语法检查，并对受影响浏览器行为验证。保留有效的碰撞、时间、炸药和暂停回归。

### 第 15 步：动态商店价格与界面整合

#### 2. 本步完成后

商店按下一关难度生成固定报价，价格随难度适度上涨，购物仍有预算取舍。继续游戏后商品、报价、购买次数和交易结果保持一致。

#### 3. 实现范围

1. 根据下一关难度和收益参数生成正整数价格，首次进入时固定。本店停留、购买和恢复期间不重新定价。
2. 商品卡片、钱包检查、按钮禁用原因和实际扣款使用同一报价来源。
3. 将报价纳入第 13 步商店存档及数据校验；恢复时重建正常交易关联，不重抽商品或重置购买。
4. 每次成功购买后保存扣款、库存、购买次数和增益；失败购买不改变资金或次数。
5. 检查收益倍率下的实际增值金额，更新道具描述，避免继续写死“钻石 250 → 375”等不适用数值。
6. 展示下一关关号、目标、钱包、“已购买 X / 4 件”及必要的保存提示，保持页面简洁。
7. 根据一关收入与跨关钱包校准涨幅，让后期购物仍需要预算；记录完整价格规则和调参依据。

继续保留七种商品池、固定炸药加随机三种、四槽展示、四件限购、不刷新、不补货、非炸药单店限一份、炸药库存上限五枚和跳过购买。

力量、黄金和钻石增值、延时、护符及幸运符仍沿用原效果。动态价格不能改变物品作用范围或奖励概率。

#### 4. 验证与完成条件

| 检查 | 必须得到的结果 |
| --- | --- |
| 第 19、29、39 关商店 | 分别按第 20、30、40 关参数显示目标与报价 |
| 报价和扣款 | 正整数、金额一致，UI 禁用理由与规则一致 |
| 买两件后退出继续 | 原报价、资金、库存、效果及“2 / 4 件”恢复 |
| 连买炸药与第五次交易 | 每枚计一件，库存不超过五枚，限购后不扣款 |
| 缺钱、库存满或重复购买 | 交易失败，金额及购买次数不变 |
| 相同种子及同一商店 | 商品可复现，本店不重抽、不替换、不重新定价 |
| 收益倍率及道具文案 | 实际入账、卡片描述和效果范围一致 |
| 预算与布局 | 初期商品可合理购买，后期仍有预算取舍；桌面和短屏操作可用 |

预算检查包含多种商品组合、不同钱包及跳过购买的情况；记录可购买件数或组合和采用的收入样本。不能只证明价格上涨，就认定购物取舍已经成立。

执行针对性的规则交易检查、真实浏览器购买/刷新/继续检查和布局检查；必要时重新验证受本步影响的金币奖励与存档。不因纯价格变化重复不受影响的长流程。

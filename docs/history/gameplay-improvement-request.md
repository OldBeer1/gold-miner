# 黄金矿工：抓取体验、成就调整与项目清理需求

记录日期：2026-10-05。基线：已发布 v1.4.1，当前挑战规则 1.4.0。

**状态：需求已记录，尚未实施。** 本次只整理需求和步骤，不调整游戏代码、成就目录或玩家存档。后续发行版本、规则版本及最终参数在第 30 步定稿。

## 1. 用户提出的三个需求

1. **被抓取物太小，很难抓取到。** 增大目标的可见尺寸，改善瞄准与抓取容错，让正常出钩更容易命中。
2. **删除很难的成就，增加几个简单或适中的成就。** 减少极限时机、低概率随机结果和过长流程的要求，让普通游玩也能持续获得成就反馈。
3. **精简、整合、删除过时文档或代码，处理前先备份。** 先完成前两项游戏需求及其验收，再创建新的清理前备份，清理确认冗余的内容，最后同步文档与发布。

执行顺序以用户最新要求为准：**备份 → 游戏需求实现 → 功能验收 → 再备份 → 清理整合文档和过时代码 → 回归检查 → 最终文档与版本交付**。不要提前开展清理，也不要仅整理文档而停下游戏实施。

以下具体数值、移除清单和新成就均为实施建议，尚未成为现行规则。当前规则仍以 [GAME_SPEC.md](game-spec-v141.md) 为准，后续状态在 [IMPLEMENTATION_PLAN.md](implementation-through-v141.md) 维护。

## 2. 调整目标与边界

- 保留像素风、三模式、单游戏更新循环、暂停／截止规则、商店和成长档案的基本流程，沿用原生技术栈与既有工具。
- 抓取体验同时考虑可见轮廓、实际碰撞与画布缩放，不能仅把图案画大而让钩子穿过可见目标。
- 优先处理小金块、钻石、红宝石、钱袋等较小目标，其他可回收物同步检查；石头和火药桶单独评估，避免意外增加遮挡或爆炸风险。
- 首轮保持时间、基础价值、回收速度、事件概率和商品价格，先验证尺寸与容错调整的实际效果，再决定是否需要额外平衡。
- 成就奖励继续为徽章／展示称号，不增加永久属性。默认沿用无限模式适用范围，Seed／每日不解锁原无限成就。
- 已有生涯、图鉴、历史报告、个人最佳和解锁成果需要保留；删除困难任务指退出当前可解锁清单，历史成果的保留不构成继续要求玩家完成该任务。

## 3. 需求一：目标尺寸与抓取容错

### 3.1 当前实现依据

当前逻辑画布为 960×640，页面会按可用空间缩放。配置中的小金块半径为 14，钻石／红宝石为 20×24，钱袋为 24×28；桌面缩放后可见尺寸会进一步变小。这是需要检查的因素，尚未完成针对本需求的瞄准体验测量。

物体尺寸来自 [js/config.js](../../js/config.js)，绘制在 [js/game.js](../../js/game.js)，碰撞、布局间距、边界与可解路线在 [js/rules.js](../../js/rules.js)。调整尺寸会同时影响布局可行性，不能只修改绘制而跳过规则验证。

### 3.2 建议方案

1. 在 1280×720、1920×1080、1280×480 上记录较小目标的实际屏幕尺寸，建立固定 Seed 和代表关卡的前后对照。
2. 优先试验较小可回收物约 **1.25～1.5 倍**的尺寸；这是试调范围，最终逐类定值，不能直接把全目录统一放大。
3. 保持像素轮廓清晰，检查摆动钩尖和目标边缘是否易于判断；绘制轮廓与抓取范围协调。
4. 如放大后仍明显难抓，可试验少量抓取容错；明确容错的用途，不把爆炸范围、生成间距或所有物体的碰撞无差别扩大。
5. 多物体同时相交仍按路径最早碰撞选中，不透过石头抓后方物体；危险物仍按原风险规则处理。
6. 同步检查矿区边界、物体间距、路障路线、备用生成与事件布局。新布局仍须满足正式规则下的 45 秒无炸药／增益达标路线。

### 3.3 验收要求

- 三种桌面视口都能清楚辨认小目标，正常瞄准的真实键鼠试玩比基线更容易抓到；保留同条件截图、抓取轨迹与结果。
- 穿过可见轮廓的钩尖按定义命中，轻微擦边行为与容错配置一致；远距离没有吸附或穿透前方障碍。
- 放大后的物体不越界、不重叠、不遮住必需路线；普通／事件／备用地图继续可解。
- 空钩、炸药、桶爆炸、截止在途、回收入账、暂停与恢复没有因尺寸调整失效。

“老练矿工”（通过 20 关）建议替换为通过 10 关目标；“矿业新贵”（累计有效成绩 100000）建议替换为累计 5000 目标。条件改变时使用新的稳定 ID，不复用旧 ID 冒充同一条件；旧解锁成果保留。

### 4.4 成就验收要求

- 简单项在正常前几关有机会获得，适中项能在合理的多关／多局游玩中推进，不依赖最后一秒或连续稀有奖励。
- 条件前后边界各有正反检查；回滚入口、重复结算、刷新商店、查看报告不重复累计或发奖励。
- 新成就默认只统计无限模式；生涯总量不能直接当作无限模式专属量，应使用现有分模式统计扣除／汇总的正确口径。
- 下架项退出未解锁清单、进度分母和新提示队列；已解锁的历史徽章／称号仍可查阅，原历史报告可正常打开。

## 5. 存档与规则版本处理

尺寸／碰撞和成就条件发生变化时，不再宣称同一规则下结果完全等同于 1.4.0。第 30 步确定新规则版本与发行版本，明确新旧赛题的派生、身份、最佳记录和分享边界。

- 保留旧 Seed／每日个人最佳及规则标记，不与新规则成绩混排比较；历史报告保持原条件与版本说明。
- 对现有入口和商店明确选择兼容旧规则继续、显式迁移或其他可审阅方案，不能静默重抽布局、改变已支付报价或清空挑战。方案在调整前定稿。
- 下架成就采用兼容保留方式处理旧 ID／解锁时间／称号／报告引用，不直接删除档案字段导致合法旧档案被判损坏。
- 新增成就能由可靠的已提交无限统计推算时可补发；不能推算的条件从新版本起记录，不虚构旧单关成果。
- 修改前保存旧档案测试样本；如需迁移，保留原文备份、拒绝保存和外部修订保护，并覆盖 v1.1.0／v1.2.0／v1.4.0 档案路径。
